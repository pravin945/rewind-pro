# Project: MotorShop Manager – Motor Rewinding & Sales Management App

Act as a Senior Flutter Developer, Mobile Application Architect, Database Designer, and UI/UX Engineer.

I want you to develop a complete, production-quality Android mobile application for a small motor rewinding and motor pump sales business.

This application is exclusively for the shop owner. It will be installed directly on his Android mobile phone. It will NOT be published on the Google Play Store or any other platform.

The application must work offline and must not require any paid service.

## 1. Technology Stack

Use the following technologies:

- Flutter (latest stable version)
- Dart
- SQLite using Drift ORM
- Riverpod for state management
- GoRouter for navigation
- Google Drive API for backup and restore
- Google Sign-In for Google account authentication
- Android WorkManager for scheduled backup
- PDF package for invoice generation
- Share Plus / native Android sharing for PDF sharing
- Native Android SMS composer for SMS messages
- Flutter Local Notifications for reminders
- Flutter Secure Storage for sensitive credentials

Do not create a backend server.

Do not use ASP.NET Core, Firebase, Supabase, paid cloud databases, paid APIs, or paid hosting.

All daily business data must be stored in the mobile's local SQLite database.

Google Drive is ONLY for backup and restore.

## 14. Google Drive Backup & Restore

This is a critical requirement.

All primary data must remain in local SQLite storage.

Integrate Google Drive using the official Google Drive API.

Use the Google Drive appDataFolder or another appropriate private application backup location.

Requirements:

1. Allow the owner to sign in with his Google account.
2. Save backup files in the application's private Drive backup location.
3. Automatically schedule backup after 10:00 PM every day.
4. Use Android WorkManager.
5. Require internet connectivity for backup.
6. If the phone is offline, retry the backup when connectivity becomes available.
7. Never interrupt shop operations during backup.
8. Maintain the latest successful backup timestamp.
9. Display backup status on the dashboard.
10. Provide a manual Backup Now option.
11. Provide a Restore Data option.
12. Keep previous backup versions, with a configurable retention limit.
13. Never overwrite the local database during restore without explicit confirmation.
14. Validate backup integrity before restoring.
15. Ensure backup is consistent, even if the database changes during backup.

Backup contents:

- Complete SQLite database
- Customer records
- Repair job records
- Bills
- Payments
- Inventory
- Stock transactions
- Settings
- Daily work records
- Necessary PDF documents, if stored locally

Use an encrypted backup archive.

Protect encryption keys appropriately. Never hardcode secrets or API keys in the source code.

Important Google Drive restrictions:

- Do not require Google Play Store publication.
- Support development installation through APK.
- Document Google Cloud Console OAuth configuration.
- Use the minimum required Google Drive permission scopes.
- Explain any OAuth verification or testing-mode restrictions.
- Do not claim that a backup succeeded until the uploaded file has been verified.

The backup must be incremental where practical, but a reliable complete backup is more important than premature optimization.
